# イテレーション1: 通常モードでSUMを1問解く

状態: 実装・自動検証完了。利用者レビュー待ち。

## 今回の完成条件

スマートフォンでSUMの問題を1問解き、採点・解説・記録の保存・再開まで使えるようにする。
まずこの操作を確認し、次の単位でIF・ハードモード・5問セットへ広げる。

- 問題文と、データ3〜5行・3列の表を上半分に表示する。
- 下半分で関数、引数の順に6択から選ぶ。記号は選択肢の文字列をそのまま使う。
- 通常モードなので選択直後に正誤を判定する。誤答は同じ段階で選び直す。
- 式を完成させるか「答えを見る」を使うと、その1問の結果を確定して保存する。
- 一度でも誤答した完成問題と「答えを見る」を使った問題は、不正解として記録する。
- 未完成問題を「新しく始める」で破棄しても、保存済みの成績を変更しない。
- 前に戻る・再読み込み・アプリを閉じた後の再開でも、回答段階と誤答の有無を保持する。
- 2問続けて正解するとSUM・通常の状態が「2連続正解」になり、再読み込みだけでは連続回数が増えない。
- 保存に失敗した場合は回答を保持し、再試行が成功するまで次の問題に進めない。

カテゴリ分けの正式な照合、Excelの説明文の厳密な引用は別の調査課題として残す。
この単位の画面はSUMを指定した通常練習とし、正式カテゴリを推測して表示しない。

## 小さな設計

ブラウザで動作するJavaScriptのWebアプリとする。開発・ビルドはViteを使う。
採点・状態遷移をDOMから独立させ、Nodeのテストランナーで確認する。
実際のスマートフォンサイズの操作はPlaywrightとChromiumで確認する。

| ファイル | 責務 |
| --- | --- |
| `src/domain.js` | 問題生成、正誤判定、1問の進行、4状態の遷移 |
| `src/storage.js` | ブラウザ保存、読み込み、保存失敗と再試行 |
| `src/main.js` | 開始・回答・解説の画面と操作 |
| `src/style.css` | スマートフォンの上下配置と表示 |

### 問題

売上の列をB列またはC列、データを3〜5行として生成する。
数値と行数・列位置を変え、直前と同じ正解範囲を避ける。
各段階の6候補は生成時に並べ替え、その問題では固定する。

問題はID、表の列と行、売上範囲、正解式・結果、各段階の候補を持つ。
通常モードの誤答候補の理由は、回答中には表示せず、回答後の説明に用いる。

### 状態

- 画面: 開始 / 回答 / 解説。
- 1問の段階: 関数選択 / 引数選択 / 確定済み。
- 回答中: 選択済みの文字列、誤答の有無、直近の誤答を保持する。
- 成績: `SUM × normal` の現在の4状態だけを保持する。
- 再開用: 現在の1問と画面・段階・選択肢の順番を保持する。

画面からは `START`、`SELECT`、`BACK`、`SHOW_ANSWER`、`HOME`、`RESUME` の操作を渡す。
確定済みの問題を再表示・再送信しても、成績は二重に更新しない。

### 保存

ブラウザのlocalStorageの1キーに、成績と現在の1問をまとめて保存する。
問題の確定と成績更新を同じ書き込みに含める。
選択の途中も保存するが、その時点では長期的な成績を更新しない。

保存失敗時は、保存しようとした状態をメモリに保持する。
再試行は同じ状態を書き直し、採点や連続正解の加算をやり直さない。
壊れた保存データは自動で上書きせず、読み込みエラーを表示する。
