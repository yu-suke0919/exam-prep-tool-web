# 試作を操作して確認する方法

## 現在の状態

アプリはクラウド環境内で実装・動作検証済みだが、外から開けるURLにはまだ公開していない。
このチャットで使えるツールには、WebアプリのプレビューURLを発行する機能がない。
クラウド内で開発サーバーを起動しても、利用者のスマートフォンからアクセスできることにはならない。

## 確認用の公開案

同じGitHubリポジトリのGitHub Pagesへ、ビルド済みの静的アプリを配信する。
公開されたサイトは、URLから誰でも閲覧できる。学習記録は引き続き各ブラウザ内に保存する。
利用者はGitHub Pagesへの一般公開を承認済み。現在は公開作業中で、サイトの配信完了はまだ確認していない。

用意した `.github/workflows/pages.yml` は手動実行専用。
リポジトリに反映してGitHub Pagesの配信元をGitHub Actionsに設定し、ワークフローを実行すると配信する。
リポジトリの公開範囲やGitHubのプランによって、Pagesの利用条件を確認する必要がある。

プロジェクト配信に必要な `/exam-prep-tool-web/` のパスをビルドに設定する。
GitHubの標準ドメインを使った場合の予定URL:

`https://yu-suke0919.github.io/exam-prep-tool-web/`

このURLは予定であり、現時点の動作確認用リンクではない。

## 公開前の検証

- `/exam-prep-tool-web/` を基準にした本番ビルドが成功。
- そのビルドをローカルの静的サーバーで配信し、スマートフォンサイズのChromiumで6択・結果表示・再読み込み後の復元を確認。
- 上記操作でHTTPエラー・JavaScript例外がないことを確認。
- GitHub Actionsの実行と実際のPagesへの配信は未実施。

## 公開作業で確認した接続制限

Gitの読み取りは成功しているが、GitHub APIへのリクエストは環境の接続制限で拒否された。
`api.github.com` と公開先の `yu-suke0919.github.io` を許可するクラウド環境の設定案を保存済み。
設定案の保存だけでは実行中の環境に反映されないため、環境設定の保存・公開後にAPI接続を再確認する。
GitHub側の認証・Pages利用条件・配信結果は、接続制限を解消してから別途確認する。

## 公開せずに確認する場合

手元のPCにソースとNode.jsを用意し、READMEの起動手順を実行する。
この方法で起動するのは手元のPC内のアプリであり、クラウド環境への接続は不要。
